view project →

01 — the challenge

The Challenge

The core challenge wasn't the Wordle mechanic itself (that part's well-documented) — it was sourcing a reliable synonym relationship and definition on the fly, from two separate APIs that don't agree on data shape.

  • Normalising two different API response formats into one internal model
  • Handling API failures gracefully mid-game without breaking the guess flow

02 — the approach

The Approach

Kept state management deliberately simple — a single game-state object updated per guess, re-rendered declaratively rather than manipulating the DOM piecemeal. API calls are cached per session so repeated guesses of the same word don't re-fetch.

03 — the build

The Build

Beyond the core loop, added a few things purely because they made testing the game more fun: a dark mode toggle, and a small confetti burst on a correct guess as visual feedback.

dark mode

04 — reflection

Reflection & Next Steps

Learned the hard way that "just use two APIs" front-loads a lot of defensive coding. If I rebuilt this, I'd add a small local fallback word list so the game degrades gracefully instead of breaking when an API is slow or down.
