01 — the problem

The Problem

Tag is simple and social, but hard to organise at scale — no one keeps track of who's out, distances get argued over, and games fizzle out. The goal was to keep the physical, spontaneous feel of the game while removing the bookkeeping friction that kills it.

  • How do you show real-time distance without turning the game into a maps app?
  • How do you make "you're caught" feel fair and immediate?

02 — the process

The Process

Started with quick paper flows for the core loop (join → catch/run → round end), then moved into low-fidelity wireframes to test the catcher/runner split before touching visual design.

early user flow
lo-fi wireframes

03 — the solution

The Solution

The final UI keeps the map secondary to the action — big, glanceable status cards for "catcher" and "runner" roles, a simple distance readout instead of a full map by default, and a single primary action per screen.

runner screen

04 — reflection

Reflection & Takeaways

Being both designer and frontend dev on this one meant design decisions got reality-checked fast — some "clever" interactions got simplified once they were actually built. Next time I'd prototype the GPS-distance interaction earlier, since it ended up shaping the whole layout.
